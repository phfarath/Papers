# p06 — Voyager (arXiv 2305.16291)

## Português

Replicação offline do mecanismo do **Voyager** em cima do CraftWorld
(`papers/envs/craft.py`), um "Minecraft-lite" determinístico com árvore
tecnológica (log → planks → stick → crafting_table → wooden_pickaxe →
cobblestone → stone_pickaxe → iron_ore → furnace → iron_ingot →
iron_pickaxe → diamond).

Componentes (§3 do paper):

- **Currículo automático (§3.2):** propõe a próxima tarefa a partir de
  inventário + tarefas completadas/falhas — o próximo marco não alcançado.
- **Skill library (§3.3):** skills = (nome, descrição, código) indexadas por
  embedding da descrição; retrieval top-5 pela consulta da tarefa; o código de
  uma skill recuperada pode ser reutilizado por **prefixo** (a skill cobre a
  subtarefa).
- **Iterative prompting (§3.3):** gerar código → executar no namespace
  restrito `run_skill_code` (com orçamento = "timeout") → feedback do env +
  erro de execução entram no próximo prompt → até 4 rounds.
- **Self-verification (critic, §3.3):** a skill só entra na biblioteca após
  o critic verificar o sucesso ("store skill only on verified success").

### Mapeamento paper → código

| Paper | Código |
|---|---|
| §3.2 automatic curriculum | handler `voyager.curriculum` + `VoyagerAgent.propose_task` |
| §3.3 skill library, embedding by description, top-5 | `SkillLibrary` (`VectorIndex`, `TOP_K=5`) |
| §3.3 iterative prompting w/ env feedback + execution errors | `VoyagerAgent._attempt`/`solve_task` (`MAX_ROUNDS=4`) |
| §3.3 self-verification antes de guardar a skill | `voyager.critic` + `solve_task` |
| código executado em sandbox | `envs/craft.py::run_skill_code` (namespace restrito + orçamento) |
| §4 ablations (no curriculum / no skill library) | `run.py`: `no-curriculum`, `no-skill-library`, `no-critic` |
| §4.3 zero-shot generalization | `run.py`: linhas "zero-shot (warm/cold)" |

### Honestidade / desvios

- O `voyager.write_code` mock tem "conhecimento de mundo" (a árvore de
  receitas) — substituto do conhecimento do LLM real — mas só recebe o texto
  do prompt (regra de honestidade). O gerador injeta bug **por linha**
  (`LINE_BUG_P=0.22`, erro de execução OU falha silenciosa de item errado):
  cadeias longas para itens profundos falham frequentemente nos 4 rounds,
  enquanto compor uma skill verificada (spliced intacta, só o delta é gerado)
  mantém o programa curto e confiável — é por isso que `no-skill-library`
  atrasa os marcos e `no-critic` polui a biblioteca com skills quebradas que
  falham depois ao serem reusadas (reproduzindo a história causal do paper).
- `no-curriculum` sorteia tarefas da lista COMPLETA de itens (`ITEMS`), com
  pré-requisitos faltando — ruidoso por natureza; o milestone table mostra
  o resultado honesto.
- Efeito também visível no zero-shot: warm library ~1 round/tarefa vs frio.

### Rodar / Run

```bash
python -m papers.p06_voyager.run --seed 0 --write-results
```

## English

Offline replication of the **Voyager** mechanism on CraftWorld (a
deterministic "Minecraft-lite" tech tree). Implements the paper's three
components: **automatic curriculum** proposing the next tech-tree milestone
from inventory/completed/failed tasks; a **skill library** of verified
(name, description, code) skills indexed by description embeddings with
top-5 retrieval and prefix-based code reuse; and **iterative prompting**
(generate → execute in the restricted `run_skill_code` namespace with an
operation budget → feed env feedback + execution errors back, up to 4
rounds) with a **self-verification critic** — skills are stored only on
verified success.

Ablations in `run.py`: no skill library, no curriculum (random tasks), no
critic; plus zero-shot generalization to a fresh env/target (`torch`) with
the warm vs cold library. See the PT section for the full paper→code mapping
and fidelity notes (the naive first attempt fails so the error→retry loop is
exercised; the no-critic ablation is honestly neutral in this env).

Results are generated by `run.py --write-results` at a fixed seed — never
hand-written, and not the paper's numbers.

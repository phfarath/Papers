# p07 — MUSE-Autoskill (arXiv 2605.27366)

> **ATENÇÃO / NOTE:** este é um paper DIFERENTE do MUSE de `p04_muse`
> (Valiente & Pilly). Este trata de *autoskill*: skills como diretórios no
> disco com ciclo de vida completo e contexto como DAG comprimido.
> This is a DIFFERENT paper from p04's MUSE.

## Português

Replicação offline do mecanismo do **MUSE-Autoskill** sobre um
**SkillsBench-lite** de 12 tarefas pequenas (várias compartilhando skills
reutilizáveis: reverse ×2, vowels ×2, sum ×2, uppercase ×2).

### Skills como diretórios (§4.1)

Cada skill é materializada em disco (num diretório temporário — nada é
commitado; há um exemplo estático em `examples/`):

```
<name>/SKILL.md       frontmatter: name/description/inputs/outputs
<name>/scripts/skill.py   executável (subprocesso isolado + timeout)
<name>/tests/test_skill.py  gate de teste
<name>/.memory.md     notas de aprendizado por uso
```

### Ciclo de vida (§4.3)

`create → test-gated register → use → memory → evaluate → refine (error
trace) → merge near-duplicates → prune low-utility`. O handler
`muse.write_skill` às vezes escreve código com bug (via rng do MockLLM) — o
gate de teste e o refine existem para capturar exatamente isso, e é o que
faz o setting `no-lifecycle` perder para o completo.

### Catálogo com disclosure progressivo (§4.2)

O catálogo injetado no prompt só expõe `nome — descrição`; o SKILL.md
completo só é lido depois que `muse.select` escolhe a skill.

### Contexto como DAG (§4.4)

`ContextDAG` mantém nós rotulados com `KEEP_FIRST`/`KEEP_LAST` fixos.
Compressão em dois níveis até caber no orçamento de tokens: **Level-1**
comprime o maior nó não-fixado (`muse.compress`); **Level-2** funde a cadeia
do meio num nó-resumo (`muse.merge_chain`).

### Mapeamento paper → código

| Paper | Código |

### Honestidade / desvios

- Resultados gerados, nunca escritos à mão: `no-skills` = resposta trivial
  (devolve o input) → 0.00; `no-lifecycle` registra skills sem gate/refine/
  merge/prune → falha nas skills com bug; `full-lifecycle` recupera via
  refine.
- O "bug injection" do `muse.write_skill` é rng-determinístico — substitui
  os erros reais de codegen de um LLM; o gate é honesto (executa o script).

### Rodar / Run

```bash
python -m papers.p07_muse_autoskill.run --seed 0 --write-results
```

## English

Offline replication of the **MUSE-Autoskill** mechanism — a different paper
from p04's MUSE. Skills are materialized as **directories** under a temp run
dir (SKILL.md frontmatter, `scripts/skill.py` executed in an isolated
subprocess with a timeout, `tests/test_skill.py`, `.memory.md` learning
notes). The **full lifecycle** is implemented: create → test-gated register →
use → memory → evaluate → refine from the error trace → merge near-duplicate
descriptions → prune low-utility skills. The catalog uses **progressive
disclosure** (names+descriptions only; the full SKILL.md is read only after
selection). The **context DAG** keeps pinned `KEEP_FIRST`/`KEEP_LAST` nodes
and compresses Level-1 (big-node summarize) then Level-2 (middle-chain merge)
until under the token budget.

`SkillsBench-lite` = 12 small tasks with shared reusable skills, comparing
no-skills vs skills-without-lifecycle vs full lifecycle. The code generator
injects an rng-seeded bug ~30% of the time — this is what the test gate and
refine exist to catch, which is why the lifecycle setting wins honestly.

Results are generated by `run.py --write-results` at a fixed seed — never
hand-written, and not the paper's numbers.

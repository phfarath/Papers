# p05 — CER: Continuous Experience Reuse (arXiv 2506.06698)

## Português

Replicação offline do mecanismo do **CER** (Continuous Experience Reuse) em
cima do MiniWeb (`papers/envs/web.py`). O CER mantém **dois módulos de memória
separados** — **dynamics** (resumos de páginas + URLs + como usá-las) e
**skills** (workflows abstratos com placeholders como `{product}`) — destilados
das trajetórias por módulos de sumarização independentes, com um **buffer** que
faz merge/deduplicação ("Summarized before" quando já coberto) e **retrieval
separado** (top-k de cada tipo) injetado no prompt do agente.

Os três settings do paper são implementados:

- **Offline (Fig. 1A):** o buffer é destilado de trajetórias fornecidas
  (scripts de demonstração) antes de qualquer episódio.
- **Online (Fig. 1B/C):** o buffer começa vazio e cresce destilando as
  próprias trajetórias do agente a cada rodada.
- **Híbrido:** começa com o buffer offline e continua destilando online.

**Pegadinha do env:** a página `http://mini.web/git/admin` existe mas não tem
link — só é alcançável digitando a URL. Ela aparece na memória de dynamics, e o
agente com CER resolve w03 enquanto o ReAct sem memória nunca acha a página.

### Honestidade / desvios

- O handler `web.act` (política ReAct) é determinístico mas segue as skills
  recuperadas em ordem e usa dynamics para navegar a URLs fora da lista —
  como um LLM real faria; resultados gerados, não escritos à mão.
- Online usa o score do env como auto-julgamento (o paper usa self-judge do
  LLM): trajetórias boas e ruins são destiladas, como em §3.2.

python -m papers.p05_cer.run --seed 0 --write-results

## English

Offline replication of the **CER** (Continuous Experience Reuse) mechanism on
MiniWeb. CER keeps **two separate memory modules** — **dynamics** (page
summaries + URLs + usages) and **skills** (abstract workflows with
placeholders like `{product}`) — distilled from trajectories by independent
summarization modules, merged/deduplicated in a **buffer** ("Summarized
before" when already covered), with **separate top-k retrieval** injected into
the agent's prompt.

All three settings are implemented: **offline** (buffer distilled from
provided demonstration trajectories), **online** (buffer grows by distilling
the agent's own trajectories each round), and **hybrid**.

**Env gotcha:** `http://mini.web/git/admin` exists but has no incoming link —
only reachable by typing the URL. It shows up in dynamics memory, so the CER
agent solves w03 while the no-memory ReAct agent never finds the page.

See the PT section for the paper→code mapping table (§3 E_i = (D_i, S_i),
separate distillation, prompt A.1 buffer dedup, §5.1 k_d = k_s = 5 separate
retrieval, Fig. 1A/B/C settings, §5.7 dynamics-vs-skills ablation).

Results are generated by `run.py --write-results` at a fixed seed — never
hand-written; the run demonstrates the mechanism offline and does not
reproduce the paper's numbers.

# p11 — A-MEM (arXiv 2502.12110)

## Português

Replicação offline do mecanismo da **A-MEM** (Agentic Memory): cada memória é
construída como uma **nota** com campos completos (content, timestamp,
keywords, tags, context, links) via `amem.note`; a nota nova é **linkada a
vizinhos top-k** por embedding (`amem.link`, `TOP_K_LINK=5`); e os vizinhos
sofrem **neighbor evolution** — atualizam seus próprios tags/contexto à luz
da nota nova (`amem.evolve`). O retrieve faz embedding top-k + expansão de
1 hop pelos links.

O `adapter.py` expõe `MemorySystem` (reset/add/retrieve) e está no registry
`papers/common/adapters.py` para os benchmarks do batch 4.

### Mapeamento paper → código

| Paper | Código |
|---|---|
| §3.2 note construction (keywords/tags/context) | `amem.note` + `Note` |
| §3.3 link generation entre top-k vizinhos | `AMemMemory.add` + `amem.link` |
| §3.3 neighbor evolution (tags/contexto) | `amem.evolve` + `n_evolutions` |
| retrieval + link expansion | `AMemMemory.retrieve` |

### Rodar / Run

```bash
python -m papers.p11_a_mem.run --seed 0 --write-results
```

## English

Offline replication of **A-MEM**: each memory becomes an agentic **note**
with full fields (content, timestamp, keywords, tags, context, links);
**link generation** connects each new note to its top-k embedding
neighbors; **neighbor evolution** lets linked neighbors update their own
tags/context in light of the new note; retrieval is embedding top-k plus
1-hop link expansion. Includes a `MemorySystem` adapter in the shared
registry for batch-4 benchmarks. Results are generated by
`run.py --write-results`, never hand-written.

## Resultados / Results

PT: o A-MEM obteve **0.31** geral no dataset de 10 personas — igual ao
EmbeddingRAG, abaixo do BM25 (0.44): o grafo de notas evolui mas a
recuperação por embedding segue sendo o gargalo (hashing embedder offline).
Eventos: ~1022 links e ~208 evoluções de vizinhos. Oráculo: 0.90.

EN: A-MEM reached **0.31** overall on the 10-persona set — matching
EmbeddingRAG, below BM25 (0.44): the note graph evolves but embedding
retrieval remains the bottleneck (offline hashing embedder). Events:
~1022 links, ~208 neighbor evolutions. Oracle ceiling: 0.90.
